# SyncPop 2차 디벨롭 계획 (Phase 2 Development)

## 📌 개요 및 배경

현재 MVP 파이프라인은 단일 `gemini-4-argon` 모델에 83분 전체 오디오를 한 번에 입력하여 통짜 분할을 수행하므로 **2단계 구간 분할에만 약 8분이 소요**되는 물리적 병목이 존재합니다.
또한 모든 단계(분할 → 가사 추출 → 검증 루프 → 후처리)가 끝난 후에야 플레이어를 여는 일괄(Batch) 방식입니다.

2차 디벨롭에서는 **"Flash/메타데이터 초고속 분할 + Thinking 심층 검증 루프"의 하이브리드 아키텍처**와 **"초벌 가사 즉시 렌더링 & 실시간 백그라운드 패치"**를 도입하여, 전체 대기 시간을 **8분에서 10~15초 수준으로 단축**하고 UX를 극대화합니다.

---

## ⚡ 실시간성 극대화 설계 (Time-to-Interactive 최적화)

사용자가 긴 로딩 화면을 기다리지 않고 **"URL 제출 후 10~15초 내에 즉시 영상을 재생하며 사용할 수 있도록"** 파이프라인을 3단계로 분리합니다.

```
[YouTube URL 입력]
       │
       ▼ (0 ~ 10초)
┌────────────────────────────────────────────────────────────────────────┐
│ 1. [초고속 분할] YouTube 메타데이터(0s) or Flash 5분 청크 병렬 분할(10s) │
└────────────────────────────────────────────────────────────────────────┘
       │
       ▼ (10 ~ 15초)
┌────────────────────────────────────────────────────────────────────────┐
│ 2. [곡별 초벌 추출] '첫 번째 곡(또는 클릭한 곡)' 1차 가사·번역 생성 (~4s)  │
└────────────────────────────────────────────────────────────────────────┘
       │
       ├─────────────────────────────────► 🌟 【 즉시 플레이어 오픈 & 재생 시작 】
       │                                       (URL 입력 후 15초 이내 화면 표출)
       ▼ (사용자가 영상을 감상하는 동안 백그라운드 비동기 처리)
┌────────────────────────────────────────────────────────────────────────┐
│ 3. [백그라운드 비동기 파이프라인]                                      │
│    ① 다음 곡들(곡 2, 곡 3...) 1차 가사 순차/병렬 사전 생성 (Prefetching)│
│    ② gemini-4-argon (thinking: high) 자율 싱크 및 떼창 환각 검증(QC)   │
│    ③ 교정 발생 시 SSE lyric_patch 이벤트로 실시간 가사 싱크 업데이트    │
│    ④ 최종 완료 후 디스크 캐시(cache/*.json) 자동 저장                 │
└────────────────────────────────────────────────────────────────────────┘
```

### Q1. 어떤 부분에서 모델 호출이 이뤄져야 하는가? (Model Call Points)

1. **Point A: 세트리스트 분할 (Tier 1)**
   - **호출 모델**: `gemini-2.5-flash` (`thinking_level: low`)
   - **역할**: 메타데이터가 없을 때 5분 단위 오디오 청크를 병렬로 스캔하여 `[song / talk / applause]` 타임라인 경계선만 초고속 추출.
2. **Point B: 곡/멘트 단위 1차 초벌 가사 추출 (Tier 2)**
   - **호출 모델**: `gemini-2.5-flash` (`thinking_level: medium`)
   - **역할**: Talk 구간 요약 추출 및 Song 구간의 0.1초 가사 타임스탬프, 영문 번역, 로마자 표기를 빠르게 생성 (곡당 3~4초 소요).
3. **Point C: 고성능 자율 검증 루프 (Tier 3 - 백그라운드)**
   - **호출 모델**: `gemini-4-argon` 또는 `gemini-2.5-pro` (`thinking_level: high`)
   - **역할**: 밴드 폭음 속 관객 떼창 환각(`crowd`/`both` vs `artist`) 판별, ±3초 오디오 재탐색 기반 0.1초 단위 시간 오차 재정렬, 누락 줄 복구.

---

### Q2. 어디까지 되어야 바로 사용자에게 화면을 띄워 보여줄 수 있는가? (최소 렌더링 조건)

사용자에게 플레이어를 노출하기 위한 최소 선행 조건은 아래 **2가지만 완료되면 즉시 가능**합니다:
1. **조건 1: 세트리스트 타임라인 목록 완료 (약 0~10초)**
   - 영상의 곡/멘트 구간 목록이 나오면 우측 세트리스트 드로어를 즉시 구성할 수 있음.
2. **조건 2: 사용자가 재생하려는 '첫 번째 곡'의 1차 가사 추출 완료 (약 +3~4초)**
   - 전체 20곡을 다 기다릴 필요 없이, **재생 시작 지점의 첫 번째 곡 1차 가사만 나오면 즉시 플레이어를 오픈하고 영상 재생을 시작**합니다.
   - **최종 Time-to-Interactive**: URL 입력 후 **약 10~15초 이내**.

---

### Q3. 사용자가 영상을 보는 동안 백그라운드에서 처리할 수 있는 것은 무엇인가?

사용자가 1번 곡을 감상하는 동안 백그라운드 워커가 다음 작업을 비동기로 수행합니다:

1. **다음 곡들의 1차 가사 사전 생성 (Prefetching & JIT)**
   - 사용자가 1번 곡을 듣는 동안 곡 2, 곡 3, 곡 4의 1차 가사를 병렬로 생성하여 세트리스트에 점진적으로 활성화.
2. **고성능 자율 검증 루프 (Background QC)**
   - `gemini-4-argon (thinking: high)`이 각 곡의 오디오와 1차 가사를 대조하며 타임스탬프 오차 및 떼창 라벨 환각을 정밀 검수.
3. **실시간 가사 패칭 (Live Patching via SSE)**
   - 오차 교정(`FIXED`)이 발생하면 SSE를 통해 `lyric_patch` 이벤트를 즉시 전송하여, 화면에서 가사 타임스탬프가 실시간으로 살짝 보정되고 `[✨ FIXED]` 배지가 뜸.
4. **최종 데이터 캐싱**
   - 전 구간 검증이 완료되면 최종 JSON을 디스크 캐시(`cache/*.json`)로 영구 저장.

## 🛠️ 백로그 및 시스템 개선 과제 (Backlog)

### 1. Task 복원 시 영상 ID 하드코딩 제거 (Generalize Cache Hydration)
- **대상**: `main.py` (`_resolve_or_hydrate_task`)
- **내용**: `if "38HUU" in task_id:` 와 같은 특정 영상 ID 하드코딩을 제거하고, 서버 재시작 시 `task_id`에 매핑되는 디스크 캐시 파일(`cache/yt_{video_id}_*.json`)이 존재하면 동적으로 Task 상태를 메모리에 자동 복원(Hydration)하도록 일반화.

### 2. 처리 중 화면(Progress Screen) 취소 및 복귀 기능
- **대상**: `static/index.html`
- **내용**: 분석 진행 터미널 화면에서 사용자가 언제든 분석을 중단하고 메인 URL 입력 화면으로 되돌아갈 수 있는 **[취소하고 돌아가기] 버튼** 추가 (활성화된 SSE EventSource를 안전하게 `close()` 처리).

| 파이프라인 단계 | MVP (단일 Argon 구조) | Phase 2 (하이브리드 구조) | 최적화 사유 |
| :--- | :--- | :--- | :--- |
| **1. 메타데이터 파싱** | 미구현 | 정규식/YouTube API (0초) | 비용 0원, 지연 0초 |
| **2. 전체 구간 분할** | `gemini-4-argon` (약 8분) | `gemini-2.5-flash` 5분 청크 병렬 (~10초) | 분할 작업은 대용량 추론 불필요 |

| **4. 자율 싱크 검증(QC)** | `gemini-4-argon` high (1~2분) | **`gemini-4-argon` / `Pro` high (백그라운드)** | **환각 방지 및 정밀 추론에 집중** |
| **Time-to-Interactive** | **약 8분 ~ 10분 대기** | **약 10초 ~ 15초 이내 (대폭 단축)** | **체감 대기 시간 약 95% 감소** |
